Connect

Trooth is a pipe, and a pipe is only worth having if something is on the other end of it. This is what the feeds connect to: the analysis layer, the agent clients, the automation tools, and the open source dashboards that can render a feed without anyone building a UI.

1. KouroB

v0.1 Open protocol Apache-2.0

Self-specializing nodes that agents attach to.

A KouroB node is not an agent, a chat memory, or an LLM wrapper. It is an independent, metered unit of knowledge that gets cheaper the more it is used. A query runs down a five-tier cascade and stops at the first tier that can answer it. Frontier models train the node; they do not serve it.

T0 compiled rules and cached SQL T1 distilled model T2 specialized model T3 frontier LLM T4 human review

Every answer leaves an ed25519-signed receipt carrying the request hash, the response hash, the tier that served it, the citations, the cost in credits, and a cryptographic pointer to the previous receipt. The ledger is append-only and hash-chained, so history cannot be quietly rewritten. 

pipx install kourob
kourob init my-cell && cd my-cell
kourob ingest fixtures/events.jsonl
kourob serve --mcp        # query, ingest, get_page, list_schemas, submit_outcome
kourob attach claude-code # also: cursor, windsurf

Why this pairs with Trooth

Trooth and KouroB were built from the same conviction, at opposite ends. Trooth makes the outside world verifiable: which upstream published a value, when, under what licence, and what it disagreed with. KouroB makes a node's own answers verifiable: which tier served them, from which events, at what cost. Neither is the other's interface. They meet in the middle, and the seams line up unusually well.

Trooth into a node

An envelope is close to an ideal ingest payload: already schema-valid, content-hashed, stamped with both the source's event time and our capture time, and carrying the licence chain. A node grounded in envelopes can cite provenance past its own boundary, all the way to the upstream publisher, instead of stopping at the node itself.

A node back into Trooth

The more interesting direction. We never publish an accuracy number without naming an independent, settleable anchor, which is why only a handful of sources can carry one. KouroB's submit_outcome with source: reality is exactly that mechanism. Settled outcomes flowing back through it are anchors, and anchors are the scarcest input this benchmark has.

Neither integration is built yet. Both are described here as intent, not as shipped work.

Of the 500 feed opportunities in our demand register, 68 are cases where computing the change is mechanical but the customer needs the interpretation. That is a node's job and not a pipe's, and it is where the two would meet first.

4. Frameworks and automation

Connector registry

5 live of 1400

1400 connectors we intend to support: 100 MCP servers and the rest data feeds. A connector becomes routable only after someone reads its licence from the source's own documentation and cites the URL. Until then it is listed here and nowhere else, and it carries no grade because nothing has been measured.

Live now

National Weather Service API

Primary US weather, and the accuracy anchor where observations grade earlier forecasts.

USGS Earthquake Hazards Program

Magnitudes are revised after publication, which is the clearest revision behaviour we have.

Bureau of Labor Statistics Public Data API

Scheduled releases, so freshness lag can be measured against a published calendar.

Federal Reserve Economic Data

Republishes BLS, so republish lag is measurable and validates lineage inference.

Open-Meteo

Derivative of NWS and others, so it demonstrates lineage lag and field disagreement.
